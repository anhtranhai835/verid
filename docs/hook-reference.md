# Hook rule reference

[Back to README](../README.md)

`SubagentStart` records the subject and input fingerprint for each mapped reviewer.
Code/test writes and new approvals invalidate an in-progress correctness review;
project writes outside `.verid/` invalidate an in-progress security review too.
Changed planning inputs also invalidate the fingerprint. `SubagentStop` discards
reports without a matching current snapshot and records `REVIEW_STALE` in the audit.
Dispatch a fresh reviewer after changes; running `taste` alone preserves the snapshot.
After upgrading, run `verid upgrade --yes` and `verid doctor` to register this hook;
on Codex, trust the new handler through `/hooks`. Pinned repo resources require
their runtime and definitions to be updated explicitly as described in the README.

`VERID_BURNT_TASK_SESSION` is a non-overridable Kanban rule. The developer selects
a task, then a fresh AI session owns it. Planning sessions, other sessions and
sessions used for earlier tasks cannot act on it. Changed spec, plan or design
requires reapproval and a new session. Resume and compaction keep the current
task. After serving, stop; the developer chooses the next task in `verid board`.
See [the Kanban workflow](kanban-workflow.md).

Repo resource definitions in `.verid/agents/`, `.verid/skills/`, `.verid/templates/`,
`.verid/hooks/`, `.verid/i18n/` and `.verid/policies/` are also protected by
`VERID_BURNT_HOOK_PROTECTED`, together with the `.verid/verid.mjs` launcher. Agents may
read them; the developer maintains these copies.

The rules cover file tools, Bash (its plain write targets are judged like a Write), MCP tools, Claude Code's `Skill`, `Agent` and `Task`, and Codex's `apply_patch` and `collaborationspawn_agent`. Codex also protects project/home `.codex/`, project/home `.agents/skills/` and verid's `plugin/` folder, treats `~/.codex/sessions/`, `history.jsonl` and its state databases as transcripts and `~/.codex/auth.json` as a secret, including a relocated `CODEX_HOME`. Unexpected errors inside verid block the call.

Roles: with a tester and a coder mapped, only the coder writes production code and only the tester (or qa, for end-to-end tests) writes tests; main and unknown agents cannot take either permission. Reviewer and security write nothing. The scope of the drafting roles (architect, planner, qa) and the known skill/agent lists are advisory: departures are audited, not blocked. A role needs the host's subagent identity.
