# Small changes

verid has no shortcut for a small change in `prep` and `recipe`: every change goes through a
module (`order`, build, review, `serve`). Only `remix` is short. This table is what the hooks
enforce today; each row names the test that asserts it.

| Mode and drive         | Situation         | Developer runs                                                   | The agent may                                                                                              | Asserted by                                                                                                                                                  |
| ---------------------- | ----------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `remix`                | Fix a line        | Nothing                                                          | Write a failing test, fix, run `verid taste`. No module is needed.                                         | `tdd.e2e`: "RAW: denies production code, allows tests and other files", "runs the whole loop together with verid taste"                                      |
| `remix`                | Refactor only     | `verid garnish` after a green run                                | Change production code while PLATED.                                                                       | `tdd.e2e`: "lets only the developer declare a refactoring session, and only on a passing run"                                                                |
| `remix`                | One blocked write | `/verid tip <reason>`, then `/verid confirm <code>`              | That exact write, once.                                                                                    | `tdd.e2e`: "lets the developer override the gate once, for that exact write"                                                                                 |
| `prep`/`recipe`, human | No task selected  | `verid board`, then `verid order <module>`, then a fresh session | Nothing: code and tests are denied (`VERID_BURNT_TASK_SESSION`), and `/verid tip` cannot lift it.          | `rules-audit.e2e`: "keeps state, Git internals, MCP configuration and unapproved code protected"; `tdd.e2e`: "will not let /verid tip lift the task session" |
| `prep`/`recipe`, human | Module ordered    | Nothing more                                                     | The normal cycle: failing test first, then code. Any file may change; the cycle does not map files to ACs. | `tdd.e2e`: "approves one module of a plan with modules, and opens production code"                                                                           |
| `prep`/`recipe`, auto  | No module open    | Sign with `verid order`                                          | Nothing in code (`VERID_BURNT_AUTO_NO_MODULE`) until the queue opens a module.                             | `auto.e2e`: "locks production code until a module is open, and code and tests while stuck"                                                                   |
| `prep`/`recipe`, auto  | One blocked write | `/verid tip <reason>`, then `/verid confirm <code>`              | That exact write, once.                                                                                    | `auto.e2e`: "lets the developer tip past an auto lock once"                                                                                                  |

After a module is served, its code is locked again. A fix to served work means editing that
module's section of `.verid/plan.md` and ordering it again.
