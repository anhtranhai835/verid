# Troubleshooting

When a hook or command refuses, it prints a code such as `VERID_BURNT_TDD_NO_FAILING_TEST` and the next step.
This page lists the ones you meet first, in the order the quick start reaches them. The full list of hook rules
and overrides is in the [hook rule reference](hook-reference.md). Run `verid doctor` first: it checks setup,
hooks and runners without writing anything.

| Code                                                           | You see it when                                                                                                                                                | Why                                                                                                                        | What to do                                                                                                                                                     |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VERID_BURNT_MANIFEST_MISSING`                                 | A command or hook runs in a folder without `.verid/manifest.yaml`.                                                                                             | The project was never set up, or the shell is in the wrong folder.                                                         | Developer: run `verid cook --mode <prep\|recipe\|remix>` in the project root. Add `--test-cmd`, `--src` and `--tests` if verid does not recognise the project. |
| `VERID_BURNT_INIT_IN_AGENT`                                    | An agent runs `verid cook` or `verid upgrade`.                                                                                                                 | The agent must not be able to set verid up again.                                                                          | Developer: run the command in your own terminal, outside Claude Code.                                                                                          |
| `VERID_BURNT_RUN_NO_RUNNER`                                    | `verid taste` finds no test runner.                                                                                                                            | verid runs vitest, jest, pytest, Maven, Gradle, .NET, Go, PHPUnit or RSpec by itself; the project has none of them set up. | Set up the runner (for example `package.json` with vitest), or pass `--test-cmd` to cook, then run `verid taste` again.                                        |
| `VERID_BURNT_RUN_NO_BASELINE`                                  | `verid taste` in a `remix` project before `verid stock`.                                                                                                       | Tests that already fail must be recorded first.                                                                            | Developer: run `verid stock` in your own terminal.                                                                                                             |
| `VERID_BURNT_PLAN_NOT_APPROVED`                                | An agent writes production code before a module is approved.                                                                                                   | Production code stays locked until the developer orders a module.                                                          | Finish the module in `.verid/plan.md` (`## Module: <name>`, one `- AC-1: …` line per AC), then the developer runs `verid order <module>`.                      |
| `VERID_BURNT_MODULE_REQUIRED`                                  | `verid order` in a plan with several modules and no name.                                                                                                      | verid cannot guess which module to approve.                                                                                | Run `verid order <module>`.                                                                                                                                    |
| `VERID_BURNT_MODULE_OPEN`                                      | `verid order` while another module is open.                                                                                                                    | One module at a time.                                                                                                      | Finish and `verid serve` the open module, or edit or remove its section in `.verid/plan.md`.                                                                   |
| `VERID_BURNT_TDD_NO_FAILING_TEST`                              | An agent writes production code while the cycle is RAW.                                                                                                        | No production code without a failing test first.                                                                           | Write or fix a test, run `verid taste`, and check that it fails for the expected reason.                                                                       |
| `VERID_BURNT_TDD_TEST_FROZEN`                                  | An agent edits a test while the cycle is COOKING.                                                                                                              | A test is failing; only production code may make it pass.                                                                  | Write the minimum production code and run `verid taste`. If the test itself is wrong, stop and tell the developer.                                             |
| `VERID_BURNT_RUN_STALE`                                        | `verid taste` finishes after a file changed during the run.                                                                                                    | The run may not include the latest change, so it is not evidence.                                                          | Run `verid taste` again without editing during the run.                                                                                                        |
| `VERID_BURNT_ROLE_TESTER_ONLY` / `VERID_BURNT_ROLE_CODER_ONLY` | A test is written by the coder, or production code by the tester (Claude Code roles).                                                                          | Roles are separate.                                                                                                        | Dispatch the mapped tester for tests and the mapped coder for production code.                                                                                 |
| `VERID_BURNT_TASK_SESSION`                                     | A second or reused AI session touches code in big-brain drive.                                                                                                 | One task per AI session.                                                                                                   | Open a new session for the task that `verid order` selected.                                                                                                   |
| `VERID_BURNT_AUTO_NO_MODULE`                                   | An agent writes code in no-brain drive while no module is open.                                                                                                | The no-brain drive opens modules itself once the design is signed and the plan passes review.                              | Developer: sign with `verid order`; write `.verid/plan.md` ending with the `product` module; have the reviewer check the plan.                                 |
| `VERID_BURNT_SERVE_NOT_READY`                                  | `verid serve <module>` is refused. The detail names the gap: an AC without a passing test, no passing `verid taste`, or a review older than the latest change. | A module is served only with passing tests for every AC, a passing run with nothing changed after it, and fresh reviews.   | Close the gap the detail names: run `verid taste`, or review the module again, then serve.                                                                     |
| `VERID_BURNT_SERVE_IN_AGENT`                                   | An agent runs `verid serve`.                                                                                                                                   | Only the developer serves a module.                                                                                        | Developer: run `verid serve <module>` in your own terminal.                                                                                                    |
| `VERID_BURNT_HALTED`                                           | Every tool call is denied.                                                                                                                                     | The developer ran `verid halt`.                                                                                            | Stop and report where the work stands. Developer: run `verid resume` when ready.                                                                               |
| `VERID_BURNT_HOOK_PROTECTED`                                   | An agent edits provider settings, agent or skill definitions, commands, plugins or verid's installed code.                                                     | Those files register hooks and roles; an agent changing them could lift its own limits.                                    | Developer: make the change yourself, outside the agent session.                                                                                                |
