# Plain-language summary in the no-brain drive

In no-brain drive the person watching the board may not be a developer, and `research.md`,
`spec.md` and `design.md` are written for builders. verid signs them itself, so write
`.verid/summary.md` for that person to follow what the agent is building.

- One page, plain language: no jargon, code, file paths or requirement IDs.
- Say what will be built, what will not, the main choices made and why, and the risks or
  costs it brings.
- List each question the agent answered itself, with the answer it picked.
- Keep it in step with the documents: rewrite it whenever research, spec or design changes.

Do not wait for a reply: go on with verid:plan.
